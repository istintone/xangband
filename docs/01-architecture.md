# 1. アーキテクチャと技術仕様

## 1.1 技術選定

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | **バニラJavaScript (ES2022)** | この環境に Node 24 / Python 3.12 のみ。C/Rust/Go のツールチェーンが無い。card-eleven と同じ流儀で立ち上がりが速い |
| 実行環境 | **ブラウザ**(単一HTML、オフライン動作) | 配布が「ファイル1枚」で済む。ロジックは純粋関数なので Node からも呼べる |
| 描画 | **Canvas 2D** に等幅グリフを敷き詰める疑似ターミナル | ASCII を基本にしつつ、後からタイル画像へ差し替えられる。DOM より 80x40 グリッドの再描画が速い |
| ビルド | **build.py**(card-eleven と同一方式) | `src/js/*.js` `src/css/*.css` `src/data/*.json` を `index.html` に埋め込み直す |
| テスト | **Node で直接 require するヘッドレス検証**(`src/tests/`) | ゲームロジックが DOM 非依存なら、シード固定の再現テストが書ける |
| 依存 | **ゼロ**(外部ライブラリ・CDN を使わない) | card-eleven と同じ。オフライン単一HTMLの前提を壊さない |

### 開発フロー(card-eleven と同一)
1. `src/js/*.js` を編集
2. `python build.py` を実行
3. `index.html` をブラウザで開いて確認 / commit
- 開発時は `index.dev.html`(個別 `<script>` 読み込み)を使うとビルド不要で反復できる。
- `python build.py --check` で「埋め込み済み index.html と src が一致するか」を検証(CI/コミット前チェック)。

## 1.2 モジュール分割(`src/js/`)

JS はグローバルスコープに単純連結される(card-eleven と同じ)。
そのため**定義順は基本自由**だが、`boot.js` だけは副作用(起動)を持つので**必ず最後**に置く。

> **結合順の正本は `index.dev.html` の `<script>` の並び。**
> `build.py` / `src/tests/_setup.js` / `tools/check_code.js` はいずれも
> index.dev.html を読んで順序と層を決める。リストを三重に持たない(`[[D-23]]`)。
> 各 `<script>` は `data-layer="rule|shell"` を持つ:
> - `rule` … DOM 非依存。テストから直接ロードでき、`document`/`window` 参照を検査で禁止する
> - `shell` … 描画・入力・起動。DOM を触ってよい

```
src/js/
  rng.js        乱数。xorshift128 + シード管理。Math.random は禁止(§1.5)
  util.js       座標・距離・方向・グリッド走査などの純粋ヘルパ
  data.js       データ読み込みとテーブル索引の構築(src/data/*.json を取り込む)
  world.js      世界状態 W(全セーブ対象)の定義・生成・マイグレーション
  ── ここまで基盤 ──
  gen-common.js ダンジョン生成の共通部品(部屋配置・トンネル・階段・充填)
  gen-sites.js  サイト別生成器(方舟/灰の地表/異星遺跡/尖塔/電脳/起源)
  fov.js        再帰シャドウキャスティング視界 + 照明・センサー
  ── ここまで地形 ──
  actor.js      アクター共通(HP/エネルギー/状態異常/速度)
  player.js     プレイヤー固有(系統・ロール・能力値・経験値・レベル)
  monster.js    敵の定義参照・生成・配置・群れ
  ai.js         敵の意思決定(接近/遠隔/逃走/呼集)
  combat.js     命中・回避・ダメージ・スレイ/ブランド・クリティカル
  ── ここまで戦闘 ──
  item.js       アイテム生成・エゴ/固有品・ルーン鑑定・スタック
  inventory.js  所持品/装備スロット/重量
  ability.js    能力(旧・魔法)。系統別サブシステム・失敗率・コスト
  hazard.js     環境ハザード(減圧/放射線/汚染/監視)と気密
  power.js      セル(電力)経済。ライト/射出器/ツールの充填と消費
  ── ここまでルール ──
  cmd.js        コマンド解決(入力 → 行動 → エネルギー消費)
  turn.js       ターンループ。エネルギースケジューラ(§docs/02.1)
  hub.js        母船《アンカー》。店/倉庫/加工/降下
  net.js        電脳層(M4)
  ── ここまで進行 ──
  render.js     Canvas 疑似ターミナル描画。マップ/サイドバー/メッセージ
  ui.js         メニュー・インベントリ画面・確認ダイアログ
  input.js      キーバインドと入力ディスパッチ
  save.js       localStorage 永続化・スキーマ移行
  boot.js       起動(必ず最後)
```

### 依存の向き(不変条件)
```
  データ  →  ルール(純粋)  →  進行  →  描画/入力
```
- **ルール層(gen/actor/combat/item/ability/hazard/power)は DOM を触らない。**
  `document` `window` `canvas` への参照を持たないこと。これがヘッドレステストの前提。
- 描画層は世界状態 `W` を**読むだけ**。描画から状態を書き換えない。
- `src/tests/_setup.js` は build.py と**同じ結合順**を使う。順序を変えたら両方更新する。

## 1.4 永続化

- **保存先**: `localStorage`(単一キー `xangband.save`)。JSON + schema バージョン。
- **保存対象**: 世界状態 `W` 全体(プレイヤー・現在階・母船・鑑定済み知識・スコア・設定)。
- **パーマデス**: 死亡時にセーブを**破棄**し、墓碑(スコア記録)だけを別キー `xangband.scores` に残す。
- **セーブスカム対策**: 階層の乱数状態を保存に含める。ロードで階を引き直せない。
- **マイグレーション**: `save.js` に `migrate(save)` を置き、schema 版ごとに逐次変換。
  card-eleven と同じ「上げるだけ・落とさない」方針。
- **エクスポート/インポート**: JSON をテキストで書き出せるようにする(バックアップと不具合報告用)。

## 1.5 不変条件(壊すと破綻するルール)

1. **乱数は `rng.js` 経由のみ。`Math.random()` の直接使用を禁止**。
   → 同一シードで同一ダンジョンが再現できること。これが自動テストとバグ再現の生命線。
   `node tools/check_code.js` が `Math.random` を検出して落とす。
2. **深度(Depth)は全サイト共通の絶対値**。サイトが強さの基準を変えない(§docs/00.3)。
3. **ルール層は DOM 非依存**(§1.2)。`data-layer="rule"` の全ファイルを `check_code.js` が検査する。
4. **エネルギー消費のない行動を作らない**(無限ループ防止)。
   自由行動(インベントリを開く等)はターンを進めない「メタ操作」として明確に分離する。
5. **プレイヤーと敵は同じアクター基盤・同じスケジューラで動く**。
   本家同様、速度・状態異常の効果を左右で二重実装しない。

## 1.6 描画モデル

### 端末とマップの分離
- **端末(Terminal)**: 固定 **80x40 セル**の等幅グリッド。Canvas に自前で敷き詰める。
  - 行0 … メッセージ行
  - 列0〜12 … サイドバー(HP/深度/シード等)
  - 残り **67x39** … マップビューポート
- **マップ(Level)**: 論理サイズは端末より大きい(初期値 **120x50**、サイトごとに可変)。
- 両者は**最初から分離**し、ビューポートはプレイヤー追従でスクロールする(`[[D-21]]`)。
  後付けでスクロールを入れると描画・入力・FOV の座標系を全て触ることになるため。

### グリフ中間表現
描画は必ず **`{ ch, fg, bg }` の中間表現**を経由する(`[[D-22]]`)。

```
世界状態 W ──(render.js: 純粋な写像)──> グリフバッファ ──> 描画器
                                                          ├─ ASCII 描画器 (M0)
                                                          └─ タイル描画器 (将来)
```

- グリフバッファは 80x40 の配列。**ここまでは DOM 非依存**なので、
  「特定シードの特定ターンで画面がこう見える」というスナップショットテストが書ける。
- タイル対応は描画器を差し替えるだけで済む。`ch` にタイルIDを対応付ける表を後から足す。

### 色
16色パレット(ANSI 互換)を `render.js` に定義し、**色名で参照**する。
色覚配慮パレットへの差し替えを想定し、コードに生の `#rrggbb` を書かない。
