# 11. 独自機構の実装設計

> [[doc:concept]] §0.4 が挙げた4つの独自機構のうち、
> **(3) 電脳層** と **(4) サルベージと加工** の実装設計。
> (1) 環境ハザードは [[doc:environment]]、(2) セル経済は既に実装済み。
>
> どちらも **Angband のコア機構を壊さない差分**として設計する。
> 壊さないとは「これを一切使わなくても最後まで遊べる」という意味。

---

## 11.1 電脳層 ― なぜ第2マップを作らないか ([[D-65]])

[[doc:concept]] §0.4(3) が狙っていたのは、次の一点に尽きる。

> **ネット面での行動が物理面に反映される。**
> 隔壁を開ける / 監視を切る / 自律防衛を掌握する。

同深度の第2マップ・専用生成器・ICE敵は、**その狙いを実現する手段**であって
目的ではない。手段のほうが M4 の他の項目を全部合わせたより大きい。

そこで縮小版から始める。

| | フル実装 | 縮小版(採用) |
|---|---|---|
| 場所 | 同深度の第2マップ | 物理面に置かれた**端末** |
| 移動 | ネット面を歩く | 歩かない。端末の前で操作する |
| 敵 | ICE(専用の敵) | **判定**。ICE は敵ではなく難度になる |
| 資源 | 認知(Cognition) | **同じ**。ここは縮小しない |
| 物理面への反映 | あり | **同じ。ここが狙いなので削らない** |

**認知だけは最初から本実装する。** 縮小版の中核であり、
後から足すと全部作り直しになるため。

手応えを見てから広げる。広げるときに捨てるものが無い形にしてある。

## 11.2 認知(Cognition)

**ネット面では HP ではなく認知を削られる。**

```
認知の上限 = 5 + レベル/2 + 演算(INT)の修正 * 2 + ロール補正
```

- 数値の正本は `src/data/roles.json` の `cogBonus`。
- 回復は**時間経過のみ**。休息(`R`)で早まる。母船では全快する。
- **0 になると昏倒する**([[doc:concept]] §0.4(3))。
  `paralyzed` を数ターン受けた状態と同じ ―― つまり**物理面の肉体が無防備になる**。
  端末は安全な場所ではない。ジャックインは「今ここで背中を晒す」判断になる。

### なぜ HP と分けるのか

HP を削ると「戦闘の続き」になり、電脳層が別の軸にならない。
認知は**戦闘では減らず、休息以外では戻らない**。
そのため「まだ一回ぶん残っているか」を、戦闘とは独立に数えることになる。

## 11.3 端末とジャックイン

### 端末

床に置かれる地形(`TILE.TERM`、グリフ `Ω`)。

- 出現するのは **機械のある場所**。サイトの `termChance` が決める
  (尖塔 > 方舟 > 《起源》 > 灰 > 遺跡)。数値の正本は `sites.json`。
- 使っても消えない。**同じ端末で何度でも操作できる**が、
  同じ操作は同じ階では一度しか通らない(効果が既に出ているため)。
- 階段の上には置かない。**素通りできる場所に置くと、
  「寄り道して背中を晒すか」という判断が生まれない。**
- 接続者は能力**《仮設接続》**で足元に端末を立てられる ([[D-75]])。
  端末の出現率はサイトで20倍近く違うので、
  **ロールの機能が地形の運に依存しないようにする**。

### 操作 ―― `J` でジャックイン

端末の上で `J`。使える操作の一覧が出る。正本は `src/data/netops.json`。

| 操作 | 物理面への反映 | どのサイトで効くか |
|---|---|---|
| **区画図を引く** | 階全体を既知にする | どこでも(最も安い) |
| **在庫目録** | 階のアイテムを検出する | どこでも |
| **隔壁を開ける** | 階の扉を全て開ける。方舟では気圧が均される | 方舟 |
| **監視を切る** | 補足を解除し、しばらく再補足されない | 尖塔 |
| **自律防衛を掌握** | 視界内の機械系の敵を**停止**させる | 尖塔・方舟・《起源》 |

- **これが「監視系の破壊」の実装**([[doc:environment]] §8.3)。
  M3b では「階を移る」しか解除手段が無かった。

### ICE ―― 敵ではなく難度

```
成功率 = 55 + 接続技能 - ICE難度
ICE難度 = 操作ごとの基礎値 + 深度 / 2
```

- **失敗しても操作は起きない。認知を余分に持っていかれる。**
- 大きく失敗すると**逆探知**され、監視のあるサイトでは補足される。
- 接続技能は `roles.json` の `skills.net`。接続者が突出して高い。

### この機構が生む選択

- 認知は戦闘では戻らない。**どの階で使うか**が資源配分になる。
- 端末の前で昏倒する危険があるので、**先に周囲を掃除するか、賭けるか**。
- 接続者以外でも使えるが、失敗率が高い。
  **「使えるが向いていない」**の幅を残す(ロールを縦割りにしない)。

## 11.4 加工・解体・移植 ([[doc:concept]] §0.4(4))

> 本家は「エゴ品/固有品は拾うもの」。本作は**拾ったジャンクを解体・移植**できる。

### 解体(salvage)

母船の工房で装備を分解し、**モジュール**を得る。

- モジュールは刻印([[doc:core]] §2.8)と同じ語彙で表す。
  `加速` `火炎耐性` … 既にあるものを使い、新しい語彙を増やさない。
- **改修品(エゴ)を解体すると、その刻印が1つ取れる。** 素の装備からは何も取れない。
  → 「弱いエゴ品」に価値が生まれる。今まで売るしかなかったものが素材になる。
- 解体した装備は**戻らない**。

### 移植(transplant)

モジュールを別の装備に移す。移した装備は改修品になる。

- **深度に応じたレアパーツ**を要求する([[doc:concept]] §0.4(4))。
  供給過多にしないための制約。パーツは深部の敵が落とす。
- 1つの装備に移植できるモジュールは**2つまで**。
  無制限だと全部載せが最適解になり、選択が消える。
- 移植は失敗しない。**失敗で緊張を作らない** ―― 緊張は素材の希少さで作る。

### この機構が守っていること

| 本家の性質 | 本作での扱い |
|---|---|
| 良い装備は拾うもの | **維持**。作るほうが常に高くつく |
| 鑑定は学習である | **維持**。モジュールの語彙は刻印と同じ |
| 選択が最適解に潰れない | 移植は2枠まで。全部載せを作らせない |

**「弱いが好きな装備を育てられる」**のが狙いであって、
最強装備を組み立てる工房ではない。

## 11.5 実装の順序

1. 認知(`player.js` / `cmd.js`) ―― 他の全部がここに乗る
2. 端末と `J`(`world.js` / `net.js` / `ui.js`)
3. 操作 5種(`netops.json`)
4. 接続者の技能と補正(`roles.json`)
5. 解体・移植(`hub.js` / `craft.js`)

**1〜4 が終われば「監視系の破壊」も同時に片付く**([[doc:environment]] §8.3)。
