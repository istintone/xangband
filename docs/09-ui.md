# 9. UI の設計

> **M2 までは「動かすための UI」だった。** ここで「遊ぶための UI」に作り直す。
> 環境(§[[doc:environment]])が増えるほど、読めない情報が増えて破綻するため、
> M3 の前に整理しておく。

---

## 9.1 現状の不足(M2 時点で分かっていること)

実装しながら判明した穴を、言い訳せずに並べる。

| # | 不足 | 何が起きるか |
|---|---|---|
| U-1 | **注視/目標指定モードが無い** | 画面の `x` が何なのか調べられない。敵の知識を持っていても照会できない |
| U-2 | **目標を選べない** | 遠隔攻撃も能力も「最も近い敵」に自動で飛ぶ。奥の敵を狙えない |
| U-3 | **メッセージが1行だけ** | 1ターンに複数のことが起きると読めずに流れる。履歴も無い |
| U-4 | **キャラクター作成画面が無い** | 系統・ロールを API 経由でしか選べない。実質 terran/marine 固定 |
| U-5 | **一覧の並び順が ui.js と boot.js で二重定義** | 描画と選択がズレうる。実際コメントで自認していた |
| U-6 | **休息が無い** | HP 回復のために方向キーを連打することになる |
| U-7 | **連続移動が無い** | 通路を1マスずつ押す。本家には走る操作がある |
| U-8 | **サイドバーが 13 桁で狭い** | 全角ラベルが2桁を食う。環境値を足す余地が無い |
| U-9 | **色の意味が定義されていない** | 「赤 = 危険」なのか「赤 = 火属性」なのか一貫していない |
| U-10 | **キーを知らないと何もできない** | Angband 経験者だけが遊べる。`x` `f` `m` を知らない人は画面を見ても手が出ない |
| U-11 | **画面の記号が読めない** | `d` が何なのか調べる手段が無い(注視を知っていれば別だが、それも知らない) |
| U-12 | **マウスで遊べない** | クリックしても何も起きない |

## 9.2 画面レイアウトの改訂 ([[D-48]])

端末は 80x40 のまま(変えるとテストと描画が全部動く)。**内訳を変える。**

```
   0                    16                                            79
 0 ┌──────────────────────────────────────────────────────────────────┐
   │ メッセージ行 1 (最新)                                             │
 1 │ メッセージ行 2 (直前)                                             │
 2 ├────────────────┬─────────────────────────────────────────────────┤
   │ サイドバー      │                                                 │
   │ 16桁            │  マップビューポート 64 x 38                      │
   │                │                                                 │
39 └────────────────┴─────────────────────────────────────────────────┘
```

| 領域 | M2 | M3 | 理由 |
|---|---|---|---|
| メッセージ | 1行 | **2行** | 1ターンに複数のことが起きる。特に環境ダメージ |
| サイドバー | 13桁 | **16桁** | 全角ラベル + 数値で 13 は足りない。環境値も出す |
| マップ | 67x39 | **64x38** | 3桁と1行を譲る。マップは論理120x50 なのでスクロールで吸収 |

## 9.3 情報の階層

**常時見えるもの / 押せば見えるもの / 探せば見えるもの** を明確に分ける。

### 常時(サイドバー)
生死に直結し、**毎ターン変わりうる**ものだけ。

```
STRATA
Lv 12  EXP 4210
────────────
HP  47/ 68      ← 半分を割ると赤
集中  8/ 14      ← 能力系ロールのみ
AC  34  速度 +0
────────────
深度 23  危険 5
電力 340  食料 62
$ 1204
────────────
気密 2/3    ← ★不足時のみ赤で表示
被曝 14         環境の危険だけを出す
汚染  3
────────────
混乱  麻痺       ← 状態異常
────────────
T 41200
seed abc123
```

**原則: 安全な環境値は表示しない。** 出ている = 何か起きている。

### 押せば見えるもの(1キー)
| キー | 内容 |
|---|---|
| `C` | キャラクター(能力値・技能・耐性・**現在階の環境**) |
| `i` `e` | 所持品 / 装備 |
| `m` | 能力 |
| `M` | 敵の知識 |
| `x` | **注視/目標指定** (新設) |
| `^P` | **メッセージ履歴** (新設) |
| `?` | 操作一覧 |

### 探せば見えるもの
- 敵の詳細(倒すほど分かる — monster memory)
- 刻印(装備・被弾・解析で分かる)
- 階の有望度(歩いて初めて開示)

## 9.4 注視 / 目標指定モード ([[D-49]]) ★最重要の追加

Angband の `l`(look) と `*`(target) に相当。**これが無いのが M2 最大の穴**(U-1, U-2)。

```
x        注視モードに入る
  Tab / Space   次の対象へ (見えている敵 → アイテム → 地形の順)
  方向キー      カーソルを自由に動かす
  t / Enter     その対象を「目標」として記憶
  ESC           抜ける
```

- カーソル位置のものを**サイドバー下部に説明表示**。
  敵なら `Lore.describe()` の要約(知っていることだけ)。
- **目標は記憶される。** 以後 `f`(撃つ) と `m`(能力) はその目標へ飛ぶ。
  目標が死ぬ/見えなくなると自動で解除。
- 目標が無いときは従来通り「最も近い敵」。

### なぜ最重要か
遠隔攻撃と能力を M2 で実装したが、**「どれを狙うか」がプレイヤーの手にない**。
群れの中の1体を狙う、逃げる敵を追撃する、という選択が成立していなかった。

## 9.5 環境の表示 (§[[doc:environment]] §8.8 の実装)

| 表示 | 条件 |
|---|---|
| サイドバー `気密 2/3` | 必要気密 > 0 のとき。不足なら**赤** |
| サイドバー `被曝 14` | exposure > 0 |
| サイドバー `汚染 3` | contamination > 0 |
| 入階メッセージ | 環境ごとに一言。「気圧が低い。」「計器が振り切れている。」「暗い。」 |
| `C` 画面 | 現在階の全環境値 + 自分の耐性を並べる |
| マップ | 減圧区画の床を暗い色で描く(方舟のみ) |

## 9.6 移動と休息の補助 (U-6, U-7)

**オートエクスプロアは入れない**([[D-50]] / [[Q-05]] の解)。
理由: セル(電力)と食料の消費を「歩いた距離」で払わせる設計なので、
自動探索はその経済を丸ごと無意味にする。代わりに本家にもある2つを入れる。

| 操作 | 内容 |
|---|---|
| `Shift + 方向` | **連続移動**。壁・分岐・敵の出現・アイテム・環境変化のいずれかで停止 |
| `R` | **休息**。HP/SP が満ちるか、敵が見えるか、食料/電力が尽きるまで待つ |

- どちらも**ゲームターンを正しく消費する**(環境ダメージも食料も進む)。
  「タダで回復する」ことにはしない。
- `R` は M2 でデバッグ用の再生成に割り当てていたが、**休息へ移す**。
  再生成は `^R` に退避。

## 9.7 キャラクター作成 (U-4)

起動時 / `N`(新規) で作成画面に入る。

```
  系統を選ぶ           ロールを選ぶ           確認
  a) 地球系人類        a) 突撃兵              地球系人類 / 突撃兵
  b) 重力適応体        b) 工作員              体力 17  演算 10 ...
  ...                  ...                    HP 20   帯域 —
  → 選ぶと右に説明と能力値プレビュー           Enter で開始 / ESC で戻る
```

- **能力値のプレビューを出す。** 固定配分([[D-41]])なので事前に見せられる。
- `*` でランダム選択。`Enter` で決定。
- `?seed=xxx&lin=voidborn&role=ghost` の URL パラメータでも指定可能にする(再現用)。

## 9.8 一覧の単一定義 (U-5)

M2 で `ui.js`(描画) と `boot.js`(選択) が同じ filter を二重に持っていた。
**`UI.listFor(W, mode)` に一本化する** ([[D-51]])。

```
UI.listFor(W, mode) -> [項目...]     ← 描画も選択もこれだけを見る
UI.overlay(buf, W)  -> listFor を呼んで描く
boot.handleSelect(i)-> listFor を呼んで i 番目を取る
```

順序がズレる可能性を構造的に消す。テストで
「listFor の長さと overlay が描いた行数が一致する」を検査する。

## 9.9 色の意味 ([[D-52]])

M2 まで色は場当たりだった。**意味を固定する。**

| 色 | 意味 | 例 |
|---|---|---|
| `white` | 通常・既知 | 床、通常のアイテム |
| `lgray` `gray` | 見えている / 記憶 | 地形の明暗 |
| `dgray` | 記憶のみ・眠っている敵・未知 | 記憶した壁、睡眠中の敵 |
| `red` | **危険・不足** | HP 半分以下、気密不足、設備障害 |
| `yellow` | **注意・価値** | 階段、クレジット、固有機材、被曝 |
| `cyan` | **有利・強化** | 加速中、改修品、電力 |
| `green` | 良好 | HP 満タン付近、感染体 |
| `magenta` | **異常・汚染** | 汚染ファーム付き装備、混乱、異常系の敵 |
| `orange` | 熱・扉 | 隔壁扉、高熱、異常系 |
| `blue` `dblue` | 機械 | 自律機械の敵 |

**アイテムの色 = 品質**(白=通常 / cyan=改修品 / yellow=固有機材 / magenta=汚染)。
**敵の色 = 系統**。この2つを混ぜない。

### 色覚配慮 (M5 で実装)

`Render.PALETTE` を1箇所で差し替えられる構造は M0 から確保済み([[D-24]])。
`theme.js` がそこに流し込む値を持ち、`=` で開く表示設定から選ぶ。

| 配色 | 何をする |
|---|---|
| **標準** | 既定 |
| **色覚配慮** | 危険=暗い / 良好=中 / 警告=明るい と**輝度で三段に分ける** ([[D-79]]) |
| **高コントラスト** | 彩度より明暗をはっきりさせる |

文字サイズは枠外UI にだけ効く(`--ui-scale`)。
端末側は `fit()` が画面に合わせて自動で決めるので、指定する余地が無い。

**大前提は「色だけに情報を載せない」**([[D-52]])。
気密不足は色に加えて `2/3` の数字でも分かる。
未解析の装備は `?` が付き、**色でも中身を漏らさない**([[D-78]])。

> 代替パレットは色相を置き換えるだけでは足りない。
> 最初の実装は赤と緑の輝度差が 8 しかなく、
> 「見分けにくい配色を作り直しただけ」だった([[D-79]])。
> 三色が互いに輝度で分かれていることをテストで強制している。

## 9.11 枠外UI ― 操作パネルと凡例HUD ([[D-55]])

> **問題**: Angband の操作は「知っている人には最速、知らない人には不可能」。
> `x` `f` `m` `^P` を知らない人は、画面を見ても何をすればいいか分からない。
> ローグライク経験者だけが遊べるゲームになっている(U-10〜U-12)。

### 解決 ― 端末の**外**に DOM で置く

```
┌──────────┬───────────────────────────────┬──────────┐
│ 操作      │                               │ 凡例HUD   │
│ (クリック)│   Canvas 疑似端末 80x40        │ (今の画面)│
│          │                               │          │
│ 移動      │   @ が歩く本編                 │ ヒント    │
│ 戦う      │                               │ 見えるもの│
│ 調べる    │                               │ 状態の意味│
│ 持ち物    │                               │          │
└──────────┴───────────────────────────────┴──────────┘
```

**なぜ端末の中に入れないか**:

| 理由 | 内容 |
|---|---|
| 端末を情報で埋めない | 80x40 は既にサイドバー16桁を使っている。これ以上削るとマップが狭くなる |
| クリックできる | Canvas 上のクリック領域を自前で管理せずに済む |
| 文字を選択・コピーできる | 不具合報告に貼れる |
| スクロールできる | 長い説明を折り返さずに置ける |
| 畳める | 端末の寸法は固定のまま、パネルだけ隠せる |
| **端末の設計を汚さない** | グリフバッファは「ゲーム画面」のままでいられる |

### 操作パネル(左)

- **すべてのコマンドをボタンにする。** クリックするとキー入力と**同じ経路**を通る。
  → キーとボタンで挙動が分かれることが構造的に起きない。
- 分類は「移動 / 戦う / 調べる / 持ち物 / 進む / システム」の6つ。
- 各ボタンにキーを併記する(`x  目標を選ぶ`)。**使ううちにキーを覚える導線**にする。
- 今使えないコマンドは淡色にする(射出器が無ければ「撃つ」が淡色)。

### 凡例HUD(右) ([[D-56]])

> **原則: 「今画面にあるものだけ」を出す。全一覧を出さない。**
> 初心者が知りたいのは、目の前の `d` が何かであって、全24種の敵ではない。

| 区分 | 内容 |
|---|---|
| **ヒント** | **状況に応じた助言**。気密不足・空腹・電力切れ・階段の上・眠っている敵が隣 など |
| **見えているもの** | 今視界にある敵・アイテム・地形のグリフと名前。敵は眠っているかも出す |
| **状態の意味** | サイドバーの各項目が何かを一行で(「電力: ライトと射出器の燃料」) |

ヒントを最上部に置く。「今何をすべきか」を状況から出せると、
**チュートリアルを書かずに操作を教えられる。**

### マウスでの目標指定 ([[D-57]])

ボタンだけ押せても、**狙う相手を選べなければ遊べない**。
マップ上のクリックを注視/目標指定に繋ぐ。

| 操作 | 動作 |
|---|---|
| 隣接マスをクリック | そこへ移動(敵がいれば攻撃) |
| 敵をクリック | その敵を目標に指定 |
| それ以外をクリック | その位置を注視(何があるか凡例HUDと端末に出る) |

### 実装の分離

| 層 | モジュール | 役割 |
|---|---|---|
| rule | `legend.js` | **何を説明すべきか**を W から計算する。DOM 非依存なのでテストできる |
| shell | `panel.js` | DOM を組み立て、クリックを boot のコマンド経路へ流す |

`term.js` の寸法計算は**ウィンドウではなく `#stage` の実寸**を見る。
パネルを畳めば端末が自動で広がる。

## 9.12 レイアウトの検証 ([[D-58]])

数値のテストでは**画面の崩れが見えない**。ヘッドレスのブラウザで撮って目で見る。

```sh
node tools/shot.js                 # 既定の一式(4枚)を shots/ に出す
node tools/shot.js --size 800x600  # 画面サイズを変えて撮る
node tools/shot.js --url "?seed=x&lin=voidborn&role=ghost"
```

### これで見つかった不具合
| 症状 | 原因 |
|---|---|
| 端末の下端(ターン数・シード)が切れる | `fit()` がフォントサイズを `高さ/行数` から決めた後に `cellH = フォント × 行間` を掛けており、**18% はみ出していた**。セル寸法を先に決めてフォントを逆算する形に修正 |
| 文字が間延びして見える | セルの縦横比が**フォントの自然な比**と合っていなかった。80x40 の端末を 16:9 の領域に敷くとセルが横に広がりすぎる |
| ボタンのラベルが1文字ずつ縦に潰れる | flex で `p-sub` の 100% 折り返しが効かず、ラベルが圧縮されていた。grid に変更 |
| サイドバーの区切りが点線に見える | `\|` のグリフがセル高より低く、行間に隙間ができていた。背景色の帯に変更 |
| 狭い画面で端末が極端に小さい | 縦積みにすると、端末が最も必要とする縦を奪う。**パネルを重ねて既定で畳む**形に変更 |

### 撮る画面
`tools/shot.js` の `SHOTS` に定義する。増やすときはここに足す。
キャラクター作成 / 通常プレイ / 狭い画面 / 縦積み境界 の4枚。

## 9.13 描画の自動検査 ([[D-59]])

スクリーンショットを**目で見るだけでは 1px 単位の不具合が見つからない**。
ピクセル単位で比較する検査を別に置く。

```sh
node tools/check_render.js    # 複数の devicePixelRatio で描画を検査
```

| 検査 | 内容 |
|---|---|
| R-1 差分描画の残像 | 「A を描く → B を差分で描く」結果と「B を一から描く」結果を**ピクセル比較**する。一致しなければ、変わらなかったセルに前の文字のインクが残っている |
| R-2 端末が領域に収まる | 縦横にはみ出して端が切れていないか |

### 見つかった不具合 ― 差分描画の残像

> キャラクター作成でカーソルを動かすと、文字の頭にわずかに前の文字の縁が残る。

**原因**: セル寸法を CSS px で決め、`ctx.setTransform(dpr, ...)` で拡大していた。
dpr が小数(1.25 / 1.5 / 1.75)だと**セル境界が小数ピクセルに落ちる**。
塗り直しの `fillRect` の縁がアンチエイリアスされ、前の文字のインクを塗り残す。
差分描画は変わったセルしか塗らないので、その1px が次のフレームまで残る。

**修正**: **寸法をすべて device pixel の整数で持つ**。
変換行列は等倍のままにし、CSS 側のサイズだけを `/dpr` で縮める。
当たり判定(`cellAt`)だけは CSS px なので別に持つ。

### なぜ見逃していたか
**dpr = 1 と 2 では起きない。** 開発時のヘッドレスは既定で dpr=1 なので、
整数倍率だけを試している限り絶対に再現しない。
検査には**小数の倍率を必ず含める**(`RATIOS` に 1.25 / 1.5 / 1.75 / 2.5 を入れている)。

### 残像 その2 ― 縦方向 ([[D-60]])

> 文字の**上**にわずかに何かが入り込む。

上の修正の後もまだ残っていた。こちらは **dpr=1 でも出る**別の原因。

**原因**: フォントのインクは em box を**上下に超えることがある**
(和文のフォールバックフォント、括弧、記号など)。はみ出した分は隣のセルに描かれ、
差分描画はそのセルを塗り直さないので残る。
`maxWidth` を渡していたが、あれは**横しか止めない**。

**修正**: グリフを描く前に**セル矩形でクリップ**する。
これで「1セルのピクセルはそのセルだけが所有する」という不変条件が成立し、
差分描画が定義上正しくなる。

**性能**: 全面描画 5.1ms / 差分描画 0.16ms(1200x800, dpr=1.5)。問題にならない。

### なぜ最初の検査で見逃したか
**検査が1行しか描いていなかった。** 縦方向のはみ出しは
「上の行は変わらず、下の行だけ変わる」ときに初めて見える。
`CASES` に**複数行のケースを必ず入れる**
(上が不変・下が不変・真ん中だけ変わる の3通り)。

## 9.10 実装の段階

| 段階 | 内容 | 時期 |

## 9.21 一覧の選び方 ([[D-88]])

一覧は**2通りで選べる**。片方を捨てない。

| 方法 | 速さ | 向く場面 |
|---|---|---|
| **文字キー** (`a` `b` `c` …) | 速い | どれを選ぶか分かっている |
| **↑↓ と Enter** | 確かめられる | 何をすべきか分からない |

文脈アクション(`Space`)は**「何をすべきか分からない」ときに開く**ので、
そこで文字の対応を覚えていることを前提にできない。
カーソルで見比べてから決められる必要がある。

- `PageUp/Down` で5行、`Home/End` で端へ。
- **端で止まる。回り込ませない** ―― 行き過ぎたことに気づけなくなる。
- カーソル行には `>` を付ける。**色だけに頼らない**([[D-52]])。
- `Space` は開くのにも決めるのにも使える。
  つまり **`Space` `Space` で「今いちばん急ぐこと」を実行**できる。

## 9.20 携帯・タブレット ([[D-87]])

### 端末のサイドバーを畳む

携帯の縦画面で 80桁は読めない。**画面幅900px 以下では端末のサイドバー16桁を畳み**、
そのぶんをマップに回す。桁数の下限も 80 → 42 に下がる。

失われる情報は無い ―― サイドバーと同じ値を、
枠外の HUD が**横一列の要約札**として出す(元々 §9.11 の「左の数字の意味」が
同じものを説明していた)。

### 縦積み

```
┌─────────────┐
│ HUD (要約札)  │  状態は上
├─────────────┤
│   端末        │  サイドバー無しの純粋なマップ
│              │
├─────────────┤
│ ガイド (押せる) │  操作は親指の届く下
├─────────────┤
│ 記録          │
└─────────────┘
```

- 操作パネルは出さない。**タップ移動**([[D-86]])と
  **ガイドの押せる行動**([[D-85]])で、指だけで遊べる。
- 横長で背が低い画面(スマホ横)は、コンソールを端末の**右**に置く。
  端末は40行あるので、縦を削ると一気に読めなくなる。

### 判断は一方向に保つ

**画面幅 → 縦積みか → 端末がサイドバーを持つか**、の順で決める。
逆流させてはいけない。

最初の実装は「端末が桁数を決めた結果」を CSS のクラスにしていた。すると

> クラスがレイアウトを変える → レイアウトが実測を変える → 実測がクラスを変える

という循環になり、タブレットで
「端末にサイドバーがあるのに要約札も出る」状態で落ち着いた。

### 撮影の限界

Windows のヘッドレス Chrome は**ウィンドウを幅500px 未満にできない**。
390 を指定しても CSS の幅は 500 のままで、画像だけが 390 に切れる
―― レイアウトが壊れているように見えるが、写っていないだけ。

実機の縦画面(390)は撮影で再現できないので、
**端末の桁数とサイドバーの判断は `src/tests/run.js` が数値で検査している**。

## 9.19 タップ移動 ([[D-86]])

**既に見た場所をタップ/クリックすると、そこまで歩く。**

- 経路は**既知のマスの上しか通らない**。地図に無い道は使えない。
- 1歩ずつ通常の移動として処理する ―― **ターン・電力・食料・環境の作用は
  歩いたぶんだけ正しく払われる**。
- キーボードからは注視(`x`)でカーソルを合わせて `.`。

### 止まる条件

| 条件 | 理由 |
|---|---|
| 敵が見えた | 走る(`Shift+方向`)と同じ |
| **HP が減った** | 環境の作用は敵が見えなくても効く。方舟の真空区画を削られながら歩き続けてしまう |
| 足元に物がある | 通り過ぎさせない |
| 経路が塞がれた / 罠 | 進めない |

### オートエクスプロアではない ([[D-50]] は今も有効)

`[[D-50]]` が却下したのは**未知の場所を勝手に探索すること**で、
理由は「歩いた距離で電力と食料を払わせる経済が無意味になる」ことだった。

タップ移動は**プレイヤーが既に見た場所を指す**だけで、
消費は手で歩いたときと1歩も違わない。本家 Angband の travel と同じ位置づけ。

## 9.18 文脈アクション ― `Space` ([[D-85]])

### 問題

コマンドは25個ある。だが**どの瞬間でも意味があるのは3〜6個**で、
それがどれかは画面に出ていない。

> 覚えるべきは「25個のキー」ではなく「今できること」。

そして**その3〜6個は既に計算できている** ―― 「いま何をすべきか」(`Legend.hints`)
が30箇所で判定している。**助言を出しているのに、押せない**のが現状だった。

### 解決

`Space` で**今ここでできることの一覧**を出す。中身は `action.js` が組み立てる。

```
  今できること
  a) >  降りる          この下へ続いている
  b) g  拾う            単分子刃が落ちている
  c) f  撃つ            掃引機が見えている
  d) R  休息            HP が減っている。敵は見えない
```

- **各行にキーを併記する。** 松葉杖ではなく教材にする ――
  使ううちにキーを覚え、一覧を開かなくなるのが正しい姿。
- 実行は**キー入力と同じ経路**を通す([[D-57]])。
- 中央下部のガイドにも同じものを**押せるボタン**として出す。
  タッチでは一覧を開かずにそこから直接叩ける。

### 何を候補に挙げるか

| 文脈 | 出るもの |
|---|---|
| 足元 | 降下シャフト / 昇降機 / 端末 / 区画入口 / 落ちている物 |
| 隣接 | 敵への攻撃 |
| 視界内 | 撃つ / 能力 / 目標を選ぶ |
| 状態 | 気密不足→戻る / 瀕死→回復 / 所持品満杯→置く / 習得可能 |
| 母船 | 降りる / 降下先を選ぶ / 店に入る |

- **危険なものを先頭**に置く。並び順がそのまま優先度になる。
- 7件で打ち切る。全部載せると「今できること」でなくなる。

### `Space` の確保

`Space` は注視の対象送りに `Tab` と重複して割り当てられていた。
**`Tab` に一本化**して `Space` を空ける ――
最も押しやすいキーは、最も使う機能に割り当てる。

## 9.17 端末の幅 ([[D-84]])

端末は **80桁を下限に、画面幅に合わせて 140桁まで広がる**。行数は 40 固定。

- 16:9 の画面では 80桁だと高さで頭打ちになり、左右に黒帯が残っていた。
- マップのビューポートは `[[D-21]]` の時点から可変なので、
  **桁が増えればそのぶんマップが広く見える**。
- 行数を増やさないのは、1画面の情報量が増えすぎると端末らしさが崩れるため。
- サイドバー16桁とメッセージ2行は変わらない。増えた桁は全てマップに行く。
- オーバーレイ(所持品・店・星系マップ等)は**マップ領域の中央**に置く。
  サイドバー基準で左詰めにすると、広い画面で端に寄って見える。

## 9.16 枠外UI の再編 ― コンソール化 ([[D-82]])

M3a で端末の外に DOM パネルを置いた([[D-55]])。機能は足りているが、
**見た目がゲームの世界と地続きになっていない**。
左右のパネルは SF でいうコンソール / HUD / PipBoy そのものなので、そう見せる。

### 画面構成

```
┌──────────┬────────────────────────────┬──────────┐
│  操作     │   ゲーム端末 (Canvas 80x40)  │   HUD    │
│  (左)     │                            │   (右)   │
│          ├──────────────┬─────────────┤          │
│          │   ガイド       │  メッセージ履歴 │          │
└──────────┴──────────────┴─────────────┴──────────┘
```

- **中央下部を新設**し、横に2分割する。
- **左: ガイド**(「いま何をすべきか」)。右の HUD から**独立させる**。
  これは「今あるものの説明」ではなく**進行を促すもの**で、性質が違う。
  盤面の真下に置くほうが、視線の移動が短い。
- **右: メッセージ履歴**。端末の上2行より長く遡れる。

### 端末内のメッセージは残す

中央下部に履歴を出しても、**端末の上2行は消さない**。
パネルを全部消しても遊べることが後述の「消せる」の前提で、
メッセージが端末の外にしか無いと、消した瞬間に何も分からなくなる。

### コンソールの意匠

| 要素 | 何をするか |
|---|---|
| 走査線 | 低不透明度の横縞を全パネルに重ねる |
| 角の切り欠き | `clip-path` でパネルの角を落とす |
| 見出し | `▚ 移動` のように記号を付け、罫線で区切る |
| 発光 | 強調色にわずかな `text-shadow` |

**読みやすさが先**([[D-52]])。走査線と発光は `--crt` 変数で強度を持ち、
**高コントラスト配色では 0 にする**([[D-79]] の延長)。
意匠のために可読性を下げない。

### 消せること ([[D-83]])

`\` で表示量を3段に回す。ボタンからも同じ経路を通る([[D-57]])。

| 段 | 出るもの | 想定 |
|---|---|---|
| **全表示** | 操作・HUD・ガイド・履歴 | 初めて触る人 |
| **簡易** | ガイドと履歴のみ(左右を畳む) | 操作を覚えた人 |
| **非表示** | 端末だけ | HUD を見ない遊び方 |

**HUD はあるが HUD を見ない**という遊び方を、設定ではなく1キーで選べるようにする。
情報を減らすことがそのまま難度の選択になる ―― 難易度設定を別に作らずに済む。
