# STRATA (codename: xangband)

**Angband の機構をそのまま継承した、SF世界の深層探索ローグライク。**

恒星間サルベージ船《アンカー》の乗員となり、
**漂流艦 / 灰の地表 / 異星遺跡 / 超高層都市** という4つの現場を、
共通の「深度」スケールで **深度100** まで潜り抜ける。

- ターン制(エネルギー式)・深度スケーリング・ルーン式鑑定・改修品/固有機材・**パーマデス**
- バニラJavaScript / 外部依存ゼロ / オフラインで動く単一HTML

> **状態: M5(均衡と仕上げ)の途中。通しクリアが可能なことを実測で確認済み。**
> `index.html` をブラウザで開けば遊べる。
> M0〜M4 は完了 ―― 4サイト + 終端《起源》、環境(気密・被曝・汚染・重力)、
> 電脳層、解体と移植、ログ断片と結末、勝利と帰還まで通っている。

## 遊びかた

`index.html` をブラウザで開くだけ。インストールもサーバも要らない。

**Angband に不慣れでも遊べる。** 画面の左に**操作パネル**(全コマンドがボタン)、
右に**凡例HUD**(今見えているものの説明)、下に**ガイド**(今すべきこと)が出る。
マップをクリック/タップすれば移動・攻撃・目標指定ができる。
携帯やタブレットでは自動的に縦積みレイアウトに切り替わる。

**コマンドを覚えなくてよい。** `Space` を押すと「今ここでできること」が
文脈に応じて並び、そのまま実行できる。各行にキーが併記してあるので、
使ううちに覚えて一覧を開かなくなる。

| | |
|---|---|
| 移動 | `hjklyubn` / テンキー / 矢印 (`Shift+方向` で連続移動) |
| **今できること** | **`Space`** ― 文脈に合う行動の一覧 |
| 一覧の選択 | 文字キー、または `↑↓` と `Enter` |
| 注視/目標指定 | `x` (`Tab` 次へ / `t` 目標指定 / `.` そこへ歩く) |
| 降下/上昇 | `>` / `<` (`V` で降下先のサイトを選ぶ ― 母船でのみ) |
| 戦う | `f` 撃つ / `m` 能力 / `R` 休息 |
| 持ち物 | `i` 所持品 / `u` 使う / `w` 装備 / `e` 装備一覧 / `d` 置く / `g` 拾う |
| 調べる | `C` キャラクター / `M` 敵の知識 / `^P` メッセージ履歴 / `?` ヘルプ |
| その他 | `J` 接続(端末の上) / `L` ライト / `=` 表示設定 / `\` パネルの量 |
| セーブ | `S` セーブ / `^L` ロード / `N` 新シード / `^R` 同一シード再生成 |

`index.html?seed=xxxx&lin=voidborn&role=ghost` でシード・系統・ロールを指定できる(再現用)。

## 開発

```sh
python build.py            # src/ を index.html に埋め込む(配布物を作る)

# コミット前に通すもの
node src/tests/run.js       # 決定論 / 不変条件 / 統計 / 機構
node src/tests/panel.js     # 枠外UI(DOM スタブ)
node src/tests/gatecheck.js # 関門を越えられるか (--gear poor/plain/rich)
node tools/shot.js          # 画面を撮って目で確認 (shots/ に出力)
node tools/check_render.js  # 描画をピクセル単位で検査(複数の dpr)
node src/tests/autoplay.js  # 自動プレイ(既定200ラン。判定は --runs 1000)
node tools/gen_reference.js # 参照表の再生成 (データを変えたら必ず)
node tools/check_code.js    # コードの不変条件 K-1〜K-4
node tools/check_docs.js    # 企画書の整合性 C-1〜C-10
python build.py --check     # index.html / data-gen.js と src/ の乖離
```

開発中は `index.dev.html` を開けばビルド不要で反復できる。

**強さの判定に自動プレイを使わない。** 自動プレイはクラッシュ検出専用で、
「越えられるか」は `gatecheck.js` が装備を直接与えて測る ―― ボットの巧拙と
設計の是非を混ぜないため(理由は [docs/05](docs/05-decisions-backlog.md) の D-89)。
